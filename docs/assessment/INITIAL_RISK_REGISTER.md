# Initial Risk Register

**Universal Commerce Platform**  
*Document Version:* 2.0.0  
*Assessment Date:* 2026-10-22  
*Author:* Security & SRE Architecture Team  
*Status:* COMPLETE & VERIFIED

---

## 1. Risk Matrix Overview

Risks are categorized across four operational domains:
- **SEC**: Security & Compliance
- **OPS**: Operations & Infrastructure
- **DAT**: Data Integrity & Persistence
- **ARC**: Architecture & Integration

Impact and Likelihood are rated **Low (L)**, **Medium (M)**, and **High (H)**.

---

## 2. Risk Log & Mitigations

| ID | Domain | Risk Description | Severity | Likelihood | Mitigation Strategy | Owner | Status |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **RSK-01** | SEC | Default development credentials leaking into production. | H | M | Strict `.env.example` template; automated credential validation script; production rejects default passwords. | SecOps | Mitigated |
| **RSK-02** | OPS | ZooKeeper ephemeral znode retention after hard node reboot (`NodeExistsException`). | H | M | Structured shutdown hooks, healthcheck restart dependencies, and automated cleanup commands in `install.sh`. | DevOps | Mitigated |
| **RSK-03** | DAT | Inconsistent inventory deduction during concurrent order checkouts. | H | L | Database-level row locking with pessimistic/optimistic concurrency control; Spring `@Transactional` semantics. | Backend | Mitigated |
| **RSK-04** | OPS | Memory pressure on single host running all 23 containers (ELK, Kafka, DBs). | H | M | Docker Compose profiles separating dev, observability, and core; explicit memory limits (e.g. ES heap 1GB). | SRE | Mitigated |
| **RSK-05** | ARC | Microfrontend version drift or React multiple instance collision. | M | L | Pinned React 18.3.1 overrides in package.json; Vite federation shared singleton configuration. | Frontend | Mitigated |
| **RSK-06** | DAT | Kafka duplicate event execution leading to duplicate fulfillment. | H | L | Notification consumer checks `processed_events` table idempotently using composite key (`ORDER-{id}-{type}`). | Backend | Mitigated |
| **RSK-07** | OPS | Database schema drift across distributed microservices. | H | L | Flyway migration scripts executed automatically on boot; Hibernate `ddl-auto` enforced to `validate`. | Data Eng | Mitigated |
| **RSK-08** | SEC | Unauthenticated access to backend microservice actuator endpoints. | M | L | Actuator endpoints secured behind API Gateway; internal ports firewalled from public internet ingress. | SecOps | Mitigated |
| **RSK-09** | OPS | Disk space exhaustion caused by Elasticsearch log indexes and Kafka logs. | M | M | Log retention policies (7 days in dev/staging); periodic log rotation and curated Kafka segment cleanup. | SRE | Monitored |
| **RSK-10** | ARC | Cascading service outage when downstream dependency fails. | H | L | Resilience4j Circuit Breakers, Bulkheads, Timeouts, and fallback responses on Gateway and Order Service. | Architect | Mitigated |

## 3. Review & Escalation Procedure

1. **Daily SRE Standup**: Review any alerts generated by Prometheus and Alertmanager.
2. **Weekly Risk Review**: Assess newly identified dependencies, CVE vulnerabilities, or infrastructure bottlenecks.
3. **Emergency Escalation**: Follow `docs/operations/INCIDENT_RESPONSE.md` for P1/P2 incidents.
