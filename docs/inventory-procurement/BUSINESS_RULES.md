# Business rules (as implemented)

1. **Availability**: `available = on_hand - reserved - unavailable`, never negative. `incoming` is excluded until a receipt is accepted.
2. **Atomicity**: reservations, on-hand changes and releases are single conditional `UPDATE`s guarded by the availability predicate; two requests can never take the last unit. Warehouse stock has the same guard (`on_hand - reserved - unavailable >= 0`).
3. **Reservations**: `idempotencyKey` returns the original reservation. `allowPartial` reserves what exists and records `backorder_quantity`. Release is idempotent. Expiry job runs every 60 s (now enabled). Reconciliation report compares item `reserved` to active holds plus transfer reservations.
4. **Adjustments**: reason is mandatory; `before`, `after`, `delta`, evidence reference and actor are stored; rows are never overwritten. `|delta| > threshold` (default 20, configurable) stays PENDING until a user with `inventory:adjust-approve` other than the requester approves. Same idempotency key returns the same adjustment.
5. **Transfers**: states DRAFT, REQUESTED, APPROVED, PICKING, DISPATCHED, IN_TRANSIT, RECEIVED, COMPLETED plus REJECTED, CANCELLED, PARTIALLY_RECEIVED, LOST, DAMAGED. Approval needs `inventory:transfer-approve` and a different user than the requester, and reserves source stock. Dispatch releases the reservation and decrements source on-hand. Destination on-hand increases only by accepted (received minus damaged) quantity at receipt; over-receipt beyond what was dispatched is rejected. Cancel before dispatch releases the reservation.
6. **Purchase orders**: supplier must be APPROVED. `total = (subtotal - discount) + tax on the discounted amount + shipping`; discount cannot exceed subtotal. Lifecycle DRAFT, PENDING_APPROVAL, APPROVED/REJECTED, ISSUED, PARTIALLY_RECEIVED, RECEIVED, CANCELLED. Creator cannot approve. Rejection needs a reason. OVERDUE is derived (ISSUED or PARTIALLY_RECEIVED with expected date in the past). Issue adds `incoming`; cancel of an issued PO reverses it; a PO with received goods cannot be cancelled.
7. **Receiving**: `accepted = received - rejected - damaged`; only accepted quantity reaches stock and gets a cost layer at the PO unit cost. Over-receipt tolerance is 5% of ordered (fixed constant in procurement, not yet the per-tenant config value). `Idempotency-Key` is required; the same key replays the stored receipt; inventory is idempotent per receipt number; the PO row is locked so concurrent receipts serialize.
8. **Supplier returns**: DRAFT, then ship (inventory removes stock by FIFO layers and returns cost), then credit (accounting credit note through its API, idempotent). A failed accounting call leaves the return SHIPPED and retryable; stock is not deducted twice (inventory replays by source reference).
9. **Reorder point** `= avg daily demand x lead time + safety stock` (rounded up). Suggested quantity is `target - available - incoming`, at least the MOQ, and 0 when `available + incoming` is above the reorder point. Suggestions only create DRAFT POs.
10. **Forecast**: average daily demand = units confirmed/deducted in the window / days. No history means DEAD_STOCK (stock on hand) or NO_DEMAND; nothing is invented. Coverage days = available / demand; stockout risk when coverage < default lead time.
11. **Valuation**: FIFO value from remaining cost layers; weighted average from `cost_price x on-hand`. Units without a cost layer are reported as `uncostedUnits`, not valued.
12. **Isolation**: every query includes `tenant_id` from the verified token; cross-tenant ids return 404. Internal callbacks need the service token and a tenant UUID and fail closed.
